# 皮克敏抽直屬活動系統

依「皮克敏主題｜抽直屬活動企畫書」中的「召集任務」環節設計的小工具，
讓主持人出題、報到處人員回報，兩邊即時同步顯示進度。

- **主持端**（`host.html`）：設定並發布召集任務（皮克敏種類＋隻數、力量值條件、本輪名額），
  即時看到已上台人數與名單，並保留歷史紀錄。
- **報到回報端**（`report.html`）：只給報到處一位工作人員使用。畫面是 7 種皮克敏 × 1–9 號的
  按鍵表；確認新生的身分卡符合條件後點下對應按鍵，會立刻回報給主持端，該按鍵也會變灰、
  之後不能重複點選（代表這張卡已經被叫過一次）。

## 快速開始（本機測試，不需要任何帳號）

直接用瀏覽器打開 `index.html`（或用任何簡易伺服器開啟整個資料夾），
分別開兩個分頁進入「主持端」和「報到回報端」。

在還沒設定 Firebase 之前，系統會自動使用「本機測試模式」：靠瀏覽器的
`BroadcastChannel` + `localStorage` 同步，**只能在同一台電腦、同一個瀏覽器的不同分頁間同步**，
方便你在活動前先熟悉操作流程。畫面右上角的「連線模式」會顯示目前是哪一種模式。

## 正式上線（活動當天，不同裝置互通）

活動當天主持端和報到端通常是兩台不同裝置（例如主持人筆電＋報到處平板），
本機測試模式無法跨裝置同步，需要設定 Firebase Realtime Database（免費即可）：

1. 到 [Firebase Console](https://console.firebase.google.com/) 建立一個新專案。
2. 左側選單「建構」→「Realtime Database」→建立資料庫（地區建議選離自己近的，例如新加坡）。
3. 進入「規則」分頁，暫時設定成活動期間都能讀寫（**活動前後記得改回限制，避免長期公開暴露**）：
   ```json
   {
     "rules": {
       ".read": true,
       ".write": true
     }
   }
   ```
4. 左側「專案設定」→「一般」→捲到「您的應用程式」→新增一個「網頁應用程式」，
   複製畫面上出現的 `firebaseConfig` 物件。
5. 把內容貼到 [`js/firebase-config.js`](js/firebase-config.js)，取代裡面的 `YOUR_...` 佔位字串。
6. 重新整理頁面，右上角「連線模式」應該會變成「Firebase（跨裝置）」，
   此時不同裝置只要打開同一個網址，就能即時同步。

## 部署到 GitHub Pages

這是純前端的靜態網站，推上 GitHub 後可以直接用 GitHub Pages 發布：

1. 建立 GitHub repo，把這個資料夾整個推上去。
2. 到 repo 的 Settings → Pages，Source 選 `main` 分支、根目錄 `/`。
3. 等一兩分鐘後，會拿到一個 `https://<你的帳號>.github.io/<repo名稱>/` 的網址，
   活動當天用手機或平板打開這個網址即可，不需要另外架伺服器。

## 客製化

- 皮克敏種類、顏色、名稱：改 [`js/pikmin-data.js`](js/pikmin-data.js)。
- 數字範圍（預設 1–9）：同樣在 `js/pikmin-data.js` 調整 `PIKMIN_NUMBER_MIN` / `PIKMIN_NUMBER_MAX`。
- 版面顏色風格：改 [`css/style.css`](css/style.css)。

## 目前系統範圍

本系統只實作「召集任務」的出題與回報環節，也就是企畫書中「主持人發布召集任務 →
尋找符合條件的皮克敏組合 → 取得上台資格」這段。抽蘑菇分家、抽直屬姓名卡等實體道具
（蘑菇造型卡、姓名卡抽籤盒）仍照企畫書用實體方式進行，不在本系統範圍內。
